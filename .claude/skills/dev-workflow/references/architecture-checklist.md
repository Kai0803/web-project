# Architecture & Scalability Checklist (Rust + TypeScript)

聚焦「模組邊界對不對、之後改得動嗎、量大了撐不撐得住」。
前後端分離專案另見 I 節。

## A. 模組邊界
- 每個模組能用一句話說明職責；說不清楚代表職責過多。
- 能在不讀內部實作的情況下理解模組做什麼。
- 可以替換模組內部實作而不影響呼叫端。
- 檔案過大（超過約 500 行）視為職責過多的訊號，評估拆分。
- 沒有「utils」型的雜物模組，內容物彼此無關。
- Rust：可見性最小化，`pub(crate)` 優先於 `pub`；`mod.rs` / `lib.rs` 明確控制對外介面。

## B. 依賴方向
- 依賴單向流動：高層策略不依賴低層細節。
- 沒有循環相依（Rust 的 crate 間循環由編譯器擋下，但 module 間的糾纏仍須檢視）。
- 核心業務邏輯不直接依賴 web 框架、ORM、HTTP client 的型別。
- 外部相依以 trait（Rust）或 interface（TS）注入，而非在函式內直接建立具體實例。
- handler 層只做解析與組裝，業務規則不寫在 handler 裡。

## C. 狀態管理
- 沒有模組層級的可變全域狀態；設定與依賴以參數或 `AppState` 傳入。
- 連線池、client 等單例在明確的組裝層（`main` / bootstrap）建立，不散落各處。
- 純邏輯函式與 I/O 分離：計算函式不做網路 / 檔案 / DB 存取，便於測試。
- 可變資料的擁有者明確；共享狀態的鎖範圍清楚且不跨 `.await`。
- 前端：全域 store 只放真正跨頁共用的狀態，元件區域狀態不上提。

## D. 介面契約
- 公開介面的型別能表達契約：領域概念用 newtype / 具名型別，不是滿版 `String` 與 `i64`。
- 錯誤以具名型別表達（`thiserror`），呼叫端能分辨可重試與不可重試、使用者錯誤與系統錯誤。
- 回傳結構穩定；新增欄位不破壞既有呼叫端。
- 非同步邊界清楚；`async` 函式內沒有阻塞式 I/O（阻塞工作丟 `spawn_blocking`）。
- 公開項目有 doc comment，說明前置條件與可能的錯誤。

## E. 擴展性（水平）
- 服務是否無狀態；若有狀態（session、快取、上傳檔案），明確說明存在哪裡、多實例時如何共享。
- 不依賴單一 process 內的記憶體快取做正確性保證。
- 背景工作可安全重跑（冪等），失敗不會造成重複副作用。
- 資料庫選型與部署模型相符：SQLite 綁定單一實例，需要多實例時須先換 Postgres。

## F. 擴展性（資料量）
- 查詢與迴圈的成本隨資料量如何成長，已估算過。
- 大量資料以串流 / 分批處理，不一次載入記憶體。
- DB 查詢沒有 N+1；批次操作使用 bulk 寫入。
- 列表介面有分頁，且大表不用深 `OFFSET`（改用 keyset / cursor 分頁）。
- 查詢有對應索引；高頻查詢的欄位組合已確認走得到索引。
- 對外呼叫有 timeout、重試上限與退避策略。

## G. 可觀測性與維運
- 關鍵路徑有結構化日誌（`tracing`），含可追蹤的 request id。
- 錯誤能定位到具體模組與輸入，不只有一句「failed」。
- 設定集中管理，且啟動時驗證必要設定存在，缺少即明確失敗。
- 有明確的失敗模式說明：資料庫、外部 API 掛掉時系統行為是什麼。
- 有健康檢查端點，且真的檢查依賴而非固定回 200。

## H. 擴展點
- 預期會變動的部分（通知管道、金流、儲存後端）有替換機制。
- 沒有為「可能的未來需求」預先建立的抽象層（YAGNI）。
- 新增一種同類型實作需要改幾個檔案？超過兩個代表抽象不到位。

## I. 前後端分離
- API 契約有單一事實來源（OpenAPI 產生或共用型別），前後端不各自手寫一份。
- 認證機制明確：cookie session 或 token，以及對應的 CSRF / XSS 防護責任歸屬。
- CORS 設定為白名單，不是 `*`。
- 前端建置產物的部署方式明確：同源提供或獨立 CDN，影響 cookie 與 CORS 設計。
- 錯誤格式統一，前端有單一處理入口，不在每個呼叫點各自解讀。
- 版本演進策略：欄位新增為相容變更，移除或改名需有過渡期。

## 輸出要求
- Findings 依 Blocker / High / Medium / Low / Nit 排序。
- 每筆含：涉及模組/檔案、結構問題、對維護或擴展的具體影響、建議調整方向。
- 若建議大幅重構，同時給出「最小可行調整」選項與取捨。
- 明確區分「現在就會出問題」與「量大之後才會出問題」。
